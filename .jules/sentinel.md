## 2025-02-14 - Fix Client-Side DoS Vulnerability in File Upload
**Vulnerability:** The `FileUpload` component generated object URLs (`URL.createObjectURL`) for all files dropped into the zone *before* enforcing `maxFiles` limits. Dropping thousands of files could lead to unbounded memory allocation and Out-of-Memory (OOM) errors, freezing or crashing the browser (Client-Side DoS).
**Learning:** `URL.createObjectURL()` synchronously allocates memory in the browser. When processing potentially unbounded user inputs (like a file drop event containing thousands of files), slicing/constraining the input array must happen *before* executing expensive or stateful operations on each item. The previous logic incorrectly generated URLs for all items and then discarded the excess.
**Prevention:** Always enforce constraints (e.g., slicing arrays, checking bounds) before performing resource-intensive operations in mapping functions, particularly with `URL.createObjectURL()`, `FileReader`, or canvas rendering. Handle `undefined` configurations safely (e.g., `maxFiles !== undefined`).
