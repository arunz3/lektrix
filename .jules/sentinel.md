## 2025-06-20 - Prevent Client-Side DoS and OOM from Unbounded URL.createObjectURL

**Vulnerability:** The application was vulnerable to client-side Denial of Service (DoS) and Out-of-Memory (OOM) crashes due to unbounded processing of file uploads. Specifically, `URL.createObjectURL(file)` was being called on every uploaded file *before* enforcing constraints like `maxFiles`. An attacker could upload thousands of images at once, causing the browser to allocate massive amounts of memory for Object URLs before the array slicing limits took effect, eventually crashing the user's tab.

**Learning:** Object URLs are a memory-heavy resource because the browser must keep the underlying `Blob` or `File` data pinned in memory as long as the URL remains valid (until explicitly revoked). When processing mass file uploads, slicing or limiting an array *after* generating heavy resources creates a critical window where memory is exhausted unnecessarily. Array truncation limits must be calculated and applied synchronously *before* expensive side effects like `URL.createObjectURL` are triggered. Furthermore, arithmetic operations for array slicing limit calculations (like `Math.max(0, maxFiles - files.length)`) must explicitly handle `undefined` fallbacks, as `undefined - length` evaluates to `NaN`, which causes `.slice(0, NaN)` to return an empty array and break the upload process.

**Prevention:** To prevent this issue and similar DoS vectors in the future, arrays must be sliced to strict constraint limits (e.g., `maxFiles`) *before* executing expensive operations or creating long-lived memory references like `URL.createObjectURL` on the items. Always validate and handle limit calculation variables (like `maxFiles`) that might be `undefined` to ensure slice fallbacks operate safely.
