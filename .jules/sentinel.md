## 2025-02-28 - [Client-Side DoS/OOM in File Uploads]
**Vulnerability:** The FileUpload component allowed users to select an arbitrary number of files (e.g., thousands). The app processed *all* of them synchronously (including mapping to `URL.createObjectURL()`) *before* slicing the resulting array down to the `maxFiles` limit. This caused severe client-side Out-Of-Memory (OOM) errors and browser crashes.
**Learning:** Object URLs (`URL.createObjectURL`) consume significant browser memory because they create a persistent reference to the file blob. Generating thousands of these references, even if the resulting array is immediately truncated and discarded, forces the browser to allocate resources for files that will never be used.
**Prevention:** To prevent client-side DoS/OOM errors during mass file uploads, input arrays must be strictly validated and sliced to constraint limits (e.g., `maxFiles`) *before* executing expensive synchronous operations or resource allocations like `URL.createObjectURL` on the items. Always carefully handle `undefined` checks on constraints to avoid math evaluating to `NaN` (which ruins `.slice()`).
