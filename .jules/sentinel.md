## 2025-03-01 - Fix client-side DoS and OOM risks from uncontrolled inputs
**Vulnerability:** The application was vulnerable to client-side Denial of Service (DoS) and Out-of-Memory (OOM) errors. Text inputs lacked `maxLength` constraints, allowing excessively large string payloads to freeze the browser. Additionally, the `FileUpload` component generated object URLs (`URL.createObjectURL`) for all uploaded files before enforcing the `maxFiles` limit, causing potential OOM crashes when a user dragged hundreds of files.
**Learning:** Client-side limitations must be strictly enforced before resource-intensive browser APIs are called, and unbounded text inputs are a DoS vector even when backend validation isn't present.
**Prevention:** Always add `maxLength` attributes to `<input>` and `<textarea>` elements. Always slice data arrays to their constraint limits before passing them to memory-intensive functions like `URL.createObjectURL`. Ensure potential `undefined` constraint limits are safely handled in mathematical operations like `Math.max()`.
