## 2025-06-25 - Mitigating OOM DoS Risks During Mass File Uploads
**Vulnerability:** Client-side Denial of Service (Out-of-Memory) due to unconstrained `URL.createObjectURL()` usage. The application took all input files, created memory-intensive Object URLs for them, and *only then* sliced the array down to the `maxFiles` limit. If a user uploaded thousands of images at once, the browser would attempt to create Object URLs for all of them, leading to an immediate crash.
**Learning:** Object URLs are memory allocations. Deferring limits until after these allocations defeats the purpose of the limit and exposes a DoS vector.
**Prevention:** To prevent client-side DoS/Out-of-Memory errors during mass file uploads, arrays must be sliced to constraint limits (e.g., `maxFiles`) *before* executing `URL.createObjectURL` or any other memory-intensive operations on the items. Additionally, explicitly handle cases where the limit variable might be `undefined` when calculating remaining slots (e.g., `maxFiles !== undefined ? ... : undefined`) to prevent returning empty arrays via `NaN`.
