## 2025-02-28 - Client-Side DoS via Unbounded Inputs and OOM during File Preview
**Vulnerability:** The application had several missing `maxLength` properties on inputs and textareas (such as the email input, feedback textarea, metadata editor fields, watermarks, etc.), which could expose the application to Client-Side DoS or performance degradation via excessively large payloads or pasted text. Additionally, the file upload handler mapped `.createObjectURL` to *all* uploaded files before truncating the array via `.slice()`, leading to potential Out-Of-Memory (OOM) errors and uncontrolled browser memory consumption if a user uploaded thousands of files when only a few were actually allowed.
**Learning:** React state and browser DOM nodes can choke when handling massive inputs. Missing length limits are a common source of bugs or hangs, even in client-side-only apps. Furthermore, creating Object URLs consumes browser memory immediately and synchronously; performing this operation before enforcing array length boundaries meant memory was allocated for discarded files, causing severe performance issues.
**Prevention:** Always enforce `maxLength` on user-facing text inputs to restrict payloads. For file handling, enforce `maxFiles` limits and prune the raw array *before* mapping computationally expensive or memory-heavy operations like `URL.createObjectURL()`.
