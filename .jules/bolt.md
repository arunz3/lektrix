## 2024-06-29 - Parallelizing PDF tasks with limited concurrency
**Learning:** For client-side PDF processing (like compressing or embedding multiple images), sequential processing using a single `for` loop is a major bottleneck. However, parallelizing all pages at once using `Promise.all` can lead to Out-of-Memory (OOM) errors on large PDFs due to excessive memory consumption from concurrent canvas rendering and image data manipulation.
**Action:** Always use a limited concurrency approach (chunking) when processing multiple PDF pages. Process batches of pages (e.g., 3-5 pages) using `Promise.all` to parallelize independent asynchronous `pdf-lib` and I/O file operations (e.g., `page.render()`, `embedJpg()`), and then sequentially process the results of each chunk to preserve order and manage memory efficiently.
